# /l-idea — 대화 속 생각을 아이디어 노트로

**목적:** 떠오른 생각을 **원문 그대로 + 정리본**으로 바로 남긴다. 속도가 중요하므로 **승인 없이 바로 쓴다** ("쓰기 전에 보여 준다" 규칙의 예외).

입력: 사용자가 명령과 함께 준 입력 — 생각 한 줄, 또는 "방금 대화에서 나온 아이디어들"(이 대화에서 나온 아이디어를 모두 모은다).

## 처리 순서
1. **뽑기:** 말에서 아이디어를 뽑는다. 서로 다른 생각이면 여러 장으로 나눈다. 원문은 고치지 않고 그대로 보관한다.
2. **겹치는지 보기:** 아이디어마다
   ```bash
   lantern idea find "<핵심 단어 두세 개>"
   ```
   - 같은 아이디어가 있으면 **새로 만들지 않는다.** 그 카드의 `## 원문`에 날짜와 함께 덧붙이고(`> …` 인용), 정리본에 새 내용만 보탠다.
   - 같은 아이디어가 ❌ 버림 상태면, 지난 이유(`dropped_reason`)를 알려 주고 "다시 살릴까요?"를 묻는다. 살리면 `lantern idea status IDEA-NNN "새 아이디어" --note "다시 나옴"`.
   - 같은 아이디어가 🚧 막힘 상태면, 막힌 이유와 다시 볼 조건을 알려 주고 그 조건이 이루어졌는지 묻는다.
3. **유형 정하기** (`docs/0. 템플릿/_meta/enums.yaml`의 `idea_kind`): ✨ 기능 · 🔧 개선 · 🐞 버그 · 🧪 실험 · 🔍 기술 검토. 버그도 여기 모은다 (할 일 후보는 한 곳에).
4. **만들기 · 채우기:**
   ```bash
   lantern scaffold idea "<짧은 제목>" --kind 기능 --raw "<사용자 원문>"
   ```
   만들어진 파일의 빈칸만 채운다: 한 줄 요약(필수) · 왜 좋은가 · 관련 문서(링크만 — 내용 복사 금지). 모르면 `❓ 확인 필요`. 쓸 것이 없는 선택 칸은 지운다.
5. **한 줄로 알린다:** `💡 IDEA-014 카카오 로그인 (기능) 기록함` (여러 장이면 한 줄씩)

## 상태는 스킬이 바꾼다
💭 새 아이디어(`/l-idea`) → 🔍 검토 중 · 📦 작업됨(`/l-plan`) / 🗄 보류 · ❌ 버림(사람). 사람이 보류 · 버림을 말하면:
```bash
lantern idea status IDEA-014 "보류"
lantern idea status IDEA-014 "버림" --reason "<이유 한 줄 (필수)>"
```
버린 아이디어는 지우지 않는다.

## 막힌 아이디어
원하지만 지금은 못 하는 것(기술 한계 · 실력 · 경험 · 데이터 부족)은 보류가 아니라 막힘으로 둔다. 보류은 그냥 미룬 것이고, 막힘은 무엇이 되면 다시 볼지가 있다.
```bash
lantern idea status IDEA-014 "막힘" --reason "<무엇 때문에 막혔나 · 시도해 본 것>" --revisit "<무엇이 되면 다시 보나>"
lantern debt promote IDEA-014 "<익힐 것>"   # 사람의 실력 때문에 막혔을 때만: 🛠 역량 카드를 만들어 서로 잇는다
```
- `--revisit`은 확인할 수 있게 쓴다. 나쁜 예: "나중에 기술이 좋아지면". 좋은 예: "표 구조까지 읽는 HWP 도구가 생기면".
- 두 값은 사람이 말한 것을 쓴다. 모르면 묻는다. 막힌 목록은 `개발문서 MOC.md`에서 모아 본다.

