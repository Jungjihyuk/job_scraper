# 도메인 분류 키워드 분석 — 문제 정의 및 해결 방안

## 배경

ContentAnalyzer는 rule-based 키워드 매칭으로 채용공고의 산업 도메인(10개)과 핵심 기술(10개)을 분류한다.
`domain_skill.ipynb`에서 n-gram 빈도 분석과 TF-IDF 분석을 수행하여 키워드 후보를 탐색하였고,
그 과정에서 다음 세 가지 문제가 확인되었다.

---

## 문제 1: position_detail 내용 부족

### 정의

`position_detail` 컬럼이 비어있거나 매우 짧은 공고가 존재한다.
이 경우 해당 컬럼만으로는 도메인을 유추할 수 있는 키워드가 부족하여 분류가 불가능하다.

### 영향 범위

- `position_detail`이 비어있는(0자) 공고 수 확인 필요
- 50자 미만인 공고는 의미 있는 키워드 추출이 어려움
- n-gram 빈도 분석 시 빈도수가 모두 1인 경우, Top-N 선정이 사전순 정렬에 따른 우연에 불과

### 해결 방안

| 방안 | 설명 |
|------|------|
| **fallback 전략** | `position_detail`을 우선 사용하되, 길이가 부족하면(예: 50자 미만) `main_tasks + requirements + preferred`를 합산하여 분석 |
| **컬럼별 가중치** | position_detail에 높은 가중치를 두되, 다른 컬럼의 키워드도 반영하는 방식 (예: position_detail 매치 x1.5, 나머지 x1.0) |
| **미분류 허용** | 텍스트가 절대적으로 부족한 공고는 `domain=NULL`로 남기고, 무리하게 분류하지 않음 |

### 적용 위치

- `backend/pipeline/normalizers/content.py` — `analyze()` 메서드에 텍스트 길이 체크 및 fallback 로직 추가

## 문제 2: 키워드 추출 품질 한계

### 정의

`position_detail` 단독 분석이 전체 컬럼 합산 분석보다 도메인 관련 키워드를 더 잘 추출하는 경향이 있지만,
그럼에도 제대로 된 도메인 키워드가 추출되는 비율이 낮다.

### 원인

1. **통계 기반 방법의 한계**: n-gram 빈도와 TF-IDF는 "통계적으로 흥미로운 단어"를 찾을 뿐, "도메인을 나타내는 키워드인가"를 판단하지 못함
2. **채용공고 특성**: 대부분의 공고가 유사한 문체와 용어를 사용하여 TF-IDF의 IDF 가중치가 효과적으로 작동하지 않는 경우가 있음
3. **한국어 토큰화 한계**: 정규식 기반 토큰 패턴은 복합어/합성어를 제대로 분리하지 못함 (예: "디지털헬스케어" → 하나의 토큰)

### 해결 방안

| 방안 | 설명 | 난이도 |
|------|------|--------|
| **형태소 분석** (노트북 섹션 [2]) | KoNLPy 등으로 명사만 추출하여 도메인 키워드 후보 정제 | 중 |
| **SBERT 키워드 추출** (노트북 섹션 [3]) | 문장 임베딩 기반으로 의미적으로 유사한 키워드 클러스터링 | 상 |
| **도메인 시드 키워드 확장** | 현재 DOMAIN_RULES의 키워드를 시드로, Word2Vec/FastText로 유사 키워드 자동 확장 | 중 |
| **position_detail + position 결합** | position(직무명)에 이미 도메인 힌트가 있는 경우 활용 (예: "금융 데이터 엔지니어") | 하 |

### 적용 위치

- `analysis/notebooks/domain_skill.ipynb` — 섹션 [2], [3] 구현
- 분석 결과를 바탕으로 `backend/pipeline/normalizers/content.py`의 DOMAIN_RULES, TECH_RULES 키워드 보강

## 문제 3: 체계적 검증 방법 부재

### 정의

키워드 추출 및 도메인 분류가 "잘 되었는가"를 판단할 정량적 기준이 없다.
현재는 눈대중(수작업 샘플 확인)으로만 품질을 평가하고 있어,
전체적인 정확도 파악과 개선 효과 측정이 불가능하다.

### 핵심 문제

- 1,504건 전수 수동 검토는 비현실적
- 키워드를 추가/수정했을 때 정확도가 올랐는지 내렸는지 측정할 방법이 없음
- 어떤 도메인이 잘 분류되고, 어떤 도메인이 누락되는지 파악 불가

### 해결 방안: Gold Standard 기반 평가 체계

#### Step 1. 평가 데이터셋 구축 (샘플링)

```
층화 샘플링 기준:
├── (A) 분류된 공고: 각 도메인에서 5건씩 (~50건)
├── (B) 미분류 공고: 50건 랜덤
└── (C) position_detail 짧은 공고: 20건
총 ~120건
```

#### Step 2. Gold Standard 라벨링

| 방법 | 장점 | 단점 |
|------|------|------|
| **수동 라벨링** | 정확도 최고 | 시간 소요 큼 |
| **LLM 보조 + 수동 검수** | 속도와 정확도 균형 | API 비용 발생 |
| **LLM 단독** | 가장 빠름 | 검증 없이는 신뢰도 불확실 |

**추천**: LLM 보조 라벨링 후 수동 검수 (LLM이 1차 분류 + 근거 제시 → 사람이 검수/수정)

#### Step 3. 정량 평가 지표

- **정확도 (Accuracy)**: 전체 중 올바르게 분류된 비율
- **도메인별 Precision / Recall / F1**: 각 도메인이 얼마나 정확하게, 빠짐없이 분류되는지
- **혼동행렬 (Confusion Matrix)**: 어떤 도메인이 어떤 도메인으로 오분류되는지 시각화

#### Step 4. 반복 개선 사이클

```
키워드 수정 → ContentAnalyzer 재실행 → gold standard 대비 재평가 → 지표 비교
```

### 적용 위치

- `analysis/notebooks/domain_evaluation.ipynb` — 샘플링, 라벨링, 평가, 재평가 전체 워크플로우
